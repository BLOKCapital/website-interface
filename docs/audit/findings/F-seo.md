# F: SEO & AI-search optimisation

Agent F · `redesign` @ `5beb0ee` · 2026-10-11

## 1. Scope & method

- Parsed `<head>` and JSON-LD from every exported page in `scratchpad/baseline-src/out/*.html` with a Node script (`tools/agent-F/head.mjs`, `ld.mjs`). Checked title, description, canonical, robots, OG, Twitter and the H1–H3 outline. Built a link graph of in-`<main>` and site-wide anchors with `links.mjs`.
- Read the SEO sources (`src/app/layout.tsx`, every `page.tsx` metadata block, `sitemap.ts`, `robots.ts`, `not-found.tsx`, `opengraph-image.tsx`, `src/lib/seo/{site,facts,schema,llms}.ts`, `JsonLd.tsx`) and compared the data they emit with the visible copy (`faqs.ts`, `audits.ts`, `milestones.ts`, `pillars.ts`, governance and security pages).
- Measured near-duplicate content between the index pages with 8-word shingle overlap.
- Checked the live production site with `curl`: redirects, www, pages.dev, `.txt` payloads, robots and sitemap. Live is the **older** site (no `/protocol`), so I only used it for host and URL behaviour. Ran 4 web searches for the brand SERP and entity confusion.
- Validation is manual against schema.org and Google's documented requirements. I did not run the Rich Results Test (no network form submission).

## 3. Proposed metadata helper (sketch for SEO-01, -02 and -05)

```ts
// src/lib/seo/metadata.ts
import type { Metadata } from "next";
import { siteConfig } from "./site";

const OG_DEFAULT = { url: "/opengraph-image", width: 1200, height: 630, alt: "BLOK Capital, non-custodial wealth management on Arbitrum" };

export function pageMetadata(p: {
  title: string | { absolute: string };
  description: string;
  path: string;              // "/security"
  social?: { title?: string; description?: string };
  images?: typeof OG_DEFAULT[]; // omit when the segment has its own opengraph-image.tsx
}): Metadata {
  const t = typeof p.title === "string" ? `${p.title} · BLOK Capital` : p.title.absolute;
  const st = p.social?.title ?? t;
  const sd = p.social?.description ?? p.description;
  return {
    title: p.title,
    description: p.description,
    alternates: { canonical: p.path },
    openGraph: { type: "website", siteName: siteConfig.name, locale: siteConfig.locale, url: p.path, title: st, description: sd, ...(p.images && { images: p.images }) },
    twitter: { card: "summary_large_image", site: siteConfig.twitterHandle, title: st, description: sd, ...(p.images && { images: p.images }) },
  };
}
```
Remove `alternates`, `openGraph.title/description/url` and `twitter.title/description` from the layout, and keep only the site-wide defaults. Check the built HTML afterwards: every page should carry its own `og:url` and an `og:image`. If a page with no `opengraph-image.tsx` loses the root image when it sets `openGraph`, pass `images: [OG_DEFAULT]`; SEO-02 showed this happens.
